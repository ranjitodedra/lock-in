# Accessibility (WCAG 2.2 AA)

Target: **WCAG 2.2 Level AA** for first-party UI. This is an automated-plus-targeted audit, not a formal certification.

## In-scope surfaces

| Surface | Coverage |
|--------|----------|
| Landing (`/`) | Playwright axe + Vitest axe on `LandingContent` |
| Login (`/login`) | Playwright axe |
| Dashboard shell | Skip link, landmarks, mobile menu `aria-expanded` |
| Applications table + toolbar | Vitest axe; company link instead of row-as-button |
| Job application form | Vitest axe; extract live region, `aria-busy`, error `aria-describedby` |

## What axe covers

CI runs `@axe-core/playwright` on public pages with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, and `wcag22aa`. Component tests use `vitest-axe` (color-contrast disabled in jsdom because computed styles are unreliable).

Serious and critical violations fail the build.

## Known exceptions

- **ChatGPT connect UI** — third-party OAuth sheet; not fully owned.
- **Lock-In intro motion dialog** — skipped when `prefers-reduced-motion: reduce` (Playwright e2e uses reduced motion). With motion on, it is a short session overlay with click/Escape/Enter to dismiss.
- **jsdom color-contrast** — not asserted in unit tests; Playwright can flag contrast on public pages.

## Existing patterns we keep

- `lang="en"` on the root document
- Skip-to-content link in the dashboard shell
- `prefers-reduced-motion` for landing, dashboard rows, and intro
- Toolbar search labels, FAQ `aria-expanded`, table `aria-sort`
